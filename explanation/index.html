The core thesis

RELIABILITY COMES FROM THE SYSTEM AROUND THE MODEL

Treat multi-agent research like a governed analytical pipeline, not a group chat.

Control plane

Python owns workflow state, concurrency, budgets, retries, validation, and release policy.

Inference plane

The OpenAI Agents SDK gives each role a bounded model loop, tools, typed output, and hosted traces.

Evidence plane

Source records, claims, artifacts, audit history, and eval results remain inspectable after the run.

Who controls what?

Python workflow
  • Selects branches and managers
  • Starts concurrent tasks
  • Enforces retries and time limits
  • Carries run state and source IDs
  • Applies deterministic validators
  • Decides whether content is released or withheld
Agents SDK runtime
  • Executes the agent turn loop
  • Calls hosted and local tools
  • Validates structured model output
  • Returns raw responses and usage
  • Emits hosted trace spans and metadata
  • Supports agents exposed as tools

The app keeps policy and reliability decisions in ordinary code. The SDK handles bounded agent execution.

Concurrency without losing failure semantics

Bounded parallelism

An asyncio.Semaphore controls API pressure. asyncio.gather preserves branch-level results.

Failure as data

Exceptions are converted to typed failed findings after retries. Managers see the missing branch and its reason.

Partial, never fabricated

If no usable evidence reaches a manager, the fallback is partial coverage, not invented synthesis.

The source ledger is chain of custody

01 | Acquire

Specialists retrieve official, legal, academic, industry, advocacy, or comparative evidence.

02 | Normalize

Every source becomes a SourceRecord with a short stable ID, URL, publisher, date, and source tier.

03 | Join

Claims refer to source IDs. URLs stay in the source record, which keeps citations resolvable and deduplicated.

04 | Validate

The workflow rejects missing references, malformed comparisons, and unsupported report claims.

Think of the ledger as data lineage for qualitative evidence: every released claim must have a reproducible path back to a source record.

Validation and re-work are residual diagnostics

Constrained repair

The re-work agent can change only flagged targets. It cannot silently rewrite healthy sections.

Auditable diff

The audit records what failed, what was withheld, the attempted revision, and the final disposition.

Fail closed by section

Unresolved unsupported content remains withheld while valid report sections can still be released.

Adversarial review is the challenger model

Primary model

The writer synthesizes manager outputs into a decision-oriented report with claims, caveats, alternatives, and source references.

Challenger model

The reviewer looks for overclaiming, omitted counterevidence, authority mismatches, weak country analogies, and unsupported recommendations.

DraftReview findingsOne bounded revisionFinal validation

Separation of roles matters: generation optimizes coherence; challenge optimizes defect discovery.

01
Prompt

The task template held constant across tests, such as the research request instructions.

An adapter that runs one candidate system, such as the full hierarchy or shallow baseline.

One scenario and its input variables, such as a legal-policy question or injection attempt.

A rule that scores the result, such as “all cited source IDs must resolve.”

The Python provider is an adapter around ResearchWorkflow

def call_api(prompt, options, context):
    config = AppConfig(
        research_provider="offline",
        enable_manager_reconciliation=True,
        enable_adversarial_review=True,
    )
    request = UserResearchRequest(
        question=context["vars"]["question"],
        mode=RunMode.FAST,
        accept_defaults=True,
    )
    package = asyncio.run(
        ResearchWorkflow(config).run(request)
    )
    return {"output": package.model_dump_json()}

A practical build sequence

1 | Contract first

Define typed inputs, outputs, statuses, IDs, and failure representations before writing prompts.

2 | Control plane

Implement workflow state, concurrency, retries, event recording, and deterministic release rules in code.

3 | Bounded agents

Give each role a narrow objective, tools, source hierarchy, scope exclusions, and structured output type.

4 | Trace every edge

Persist handoffs, results, durations, usage, source lineage, validation findings, and report revisions.

5 | Deterministic harness

Create offline fixtures and assertions for the workflow before spending tokens on live evaluation.

6 | Comparative evals

Test a shallow baseline, full system, and mechanism ablations against the same dataset.

7 | Failure drills

Inject parse failures, missing branches, bad citations, prompt attacks, and re-work failures.

8 | Release policy

Decide what is revised, withheld, or released, then make that decision auditable.

Production judgment: where to be skeptical

This architecture improves
  • Separation of research responsibilities
  • Failure localization
  • Citation and source traceability
  • Reproducible evaluation
  • Cost and latency attribution
  • Selective withholding instead of all-or-nothing failure
It does not eliminate
  • Retrieval gaps and stale sources
  • Model interpretation errors
  • Correlated errors across agents
  • Prompt and schema regressions
  • Evaluation blind spots
  • Need for human judgment on consequential policy conclusions

Multi-agent structure is useful only when it makes evidence, decisions, failures, and costs more legible.
